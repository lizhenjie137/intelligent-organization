# 使用指南

这份指南对应小辣椒中文界面。先按 [README](../README.md) 选择桌面安装版或源码运行方式；桌面版的构建状态、数据位置与启动方式见[桌面说明](DESKTOP.md)。当前服务只接受运行它的电脑上的本机访问；多账号不等于已支持跨电脑或公网协作。

## 1. 建立本地账号

登录页提供“登录”和“注册”。注册需要显示名称、登录账号、密码与确认密码；账号为 3–40 位英文字母、数字、点、下划线或短横线，密码为 12–256 位。两次密码不一致时不会发送注册请求。

首个成功注册的账号成为管理员，之后注册的账号为员工。首次页面提示不决定权限，实际角色由服务端注册时确定。注册成功会自动登录；管理员也可以在“员工与 Agent”中创建员工账号。

账号保存在运行工作空间的电脑上，密码以独立随机盐和哈希保存。无需邮箱、第三方账号或云端注册。普通员工注册不会自动获得能力核验或执行授权。

| 角色 | 可以做什么 |
| --- | --- |
| 全体成员 | 查看共享目标与公开状态，创建目标，提交自己的资料与能力申报 |
| 目标负责人或管理员 | 在允许的阶段分派任务，管理目标运行，并独立验收他人的普通交付 |
| 被分派员工本人 | 在条件满足时接取、开工、更新进展、提交自己的交付 |
| 管理员 | 管理账号、核验能力、单独授予执行权限、配置模型 |

独立验收不允许自己验收自己的普通交付；专门的人工验收节点也需要由该节点指定的人亲自处理。

## 2. 把目标变成共同任务

进入“组织协作台”，选择“新建目标”，填写目标名称、背景与验收标准。验收标准应描述可检查的结果，例如“每项建议都列明来源、负责人、交付物和验证方式”。

默认流程为需求分析、方案起草、质量检查、人工验收和复盘；它是可查看的流程模板，不是自动生成的组织结构。需要不同分工时，可在自定义流程中填写步骤及依赖。步骤的 `depends_on` 引用同一流程中的 `key`，不要创建依赖环。

同一组织的成员看到共同的目标和任务状态，不会因登录身份不同而变成各自孤立的看板。操作按钮则根据角色、负责人和任务阶段变化。

## 3. 直接分派给具体员工或 Agent

负责人或管理员在任务行点击“分派任务”或“重新分派”。窗口中可以搜索姓名、职责或类型，也可切换全部、员工和 Agent。

名单包括所有已建立账号的员工及已登记 Agent。选中后，右侧展示执行前的条件：能力是否登记与核验、是否授权、是否可用、风险与类型限制、前置任务，以及 Agent 所需的预算或模型条件等。

- 可以先分派给条件尚未齐备的成员，明确责任人。
- 分派不会自动核验能力、授予权限、启用停用成员或更换执行者。
- 条件未齐备时，任务仍显示负责人及待补原因；补齐后才能继续执行。
- 已开工、待验收、已完成、暂停或旧版流程等不允许改派的情况，会显示对应原因。

成员只可以接取分派给自己的任务。Agent 任务由有权的负责人进入“运行总览”发起下一步执行，并不会因为被选中就自动运行。

## 4. 接取、工作与公开进展

| 状态 | 下一步 |
| --- | --- |
| 待分派 | 负责人选定执行者 |
| 待接取 | 满足条件的被分派员工点击“接取任务” |
| 已接取 | 员工点击“开始工作” |
| 工作中 | 更新公开进展，发布阶段成果，完成后提交交付 |
| 待验收 | 有权的其他人独立验收，或退回继续完善 |
| 已完成 | 可按依赖关系交接指定成果，并查看后续任务 |

公开进展面向全员，避免粘贴私人资料。未验收的进度范围为 0–99%；完成后为 100%。模型生成文本、上传附件和发布阶段成果都不等于任务已经验收完成。

“任务看板 / 成果与交接 / 协作记录”视图分别用于查看责任与状态、阅读已发布成果，以及追踪公开过程。同步状态显示连接与更新情况，正常情况下约每 2 秒轮询。

## 5. 发布成果与补充材料

“发布成果”记录工作方向、当前阶段、完成摘要、下一步和待补材料。每次最多附带 10 个文件，每个不超过 32 MiB。

支持常见图片、MP4/WebM 视频，以及 PDF、文本、Markdown、CSV、JSON、ZIP 和部分 Office 文档格式。图片与支持的视频可预览，其他文件按下载方式提供；HTML/SVG 不作为网页直接展示。

附件上传后先暂存，仅上传者可见；点击发布后，该条成果及其附件才进入组织共享范围。旧私人知识文档不会因为发布其他成果而自动公开。补交材料时发布新的记录，可保留历史版本供核对。

## 6. 提交、独立验收与交接

“提交交付”用于提交实际完成的正文与证据。这些原始内容按权限提供给提交者、目标负责人和管理员，不直接等同于对全员发布。被分派的下游执行者也可获得作为任务上下文所需的已完成前置产物；这不授予对上游私人知识文档或未验收提交历史的访问权限。

普通交付由有权的其他人独立验收。退回时填写具体缺口，执行者继续工作并重新提交。专门的人工验收节点使用“独立验收”操作，由指定人员填写依据与决定。

已完成的上游任务有已发布成果后，可“交接成果”或“交接给下一位”。选择一个成果版本和已分派给员工的直接下游任务，说明下一步。服务端依据下游任务确定接收人。

接收人可确认接收资料，或退回要求补充。**接收只确认资料，不改变任务负责人、不自动开工或完成任务，也不绕过其他前置条件。** 上游返工、成果变化或下游改派后，旧交接包可能失效，界面会保留历史并说明原因。

## 7. 知识、能力与 Skill

在“知识接入”导入 `.md`、`.txt`，或粘贴文本。导入的是文件快照，不会自动同步本地原文件。个人资料和组织资料的可见与编辑权限不同。

员工在“我的能力”中选择原子能力、填写经验、自评 L1–L5，并引用原文中真实存在的证据。等级描述的是能力范围，不是权限等级；自报或资料关键词候选不等于认证。管理员核验后，仍需另行授予该能力的执行权限。

“能力目录”支持上传 Markdown 或 JSON 能力包。先解析预览，补齐名称、功能、输入、输出、验收标准等字段，再登记。给员工登记会形成待核验申报；给 Agent 登记的是能力声明。上传不会执行文件中的指令、安装依赖或接通工具。

## 8. 模型设置与 Agent 运行

管理员打开“模型配置”，填写连接类型、兼容协议、API 基础地址、模型名与所需密钥。基础地址不要包含末尾的 `/chat/completions` 或 `/messages`。

“测试当前连接”只测试当前草稿；通过后仍需“保存并启用”。状态区区分未配置、不可用、已配置未测试、测试通过与测试失败。保留、替换或清除旧密钥需明确选择；地址或协议变化时不能无提示地沿用旧密钥。

模型测试发送固定文本；真实 Agent 运行会发送完成该任务所需的资料到已配置服务。预算按 Agent 尝试次数计数。模型未连接时可以继续人工协作，Agent 执行会明确报告问题，不回退成伪装的模型答案。

## 9. 冲突、断线与本地数据

其他人更新了任务时，正在填写的内容会保留。遇到版本冲突，读取新版本、核对最新状态，再决定是否提交；不会静默覆盖他人的更新。断线时保留上次数据并暂停写操作，恢复后重新同步。

源码运行时，请在停止服务后备份整个 `data/workspace/`，同时保留附件与数据库。桌面版使用独立的 AppData 工作目录，具体路径见[桌面说明](DESKTOP.md)。不要公开上传该目录。换电脑或 Windows 账号时，加密的模型凭据可能需要重新输入。删除源码包前，先确认已另行保存需要的工作数据。
